An AI narrative that must cite its evidence

Layer ③ · the architecture behind it (C4 Component)

A seam the LLM can't cross — and a gate it can't skip

the seam downstream sees only descriptor · confidence · supporting_markers · citation → the LLM cannot invent chemistry it never receives. The Citation Audit is the NFR "every claim cited" turned into a component. Firestore rules enforce the ACL.md at the database — the real door.

Layer ③ · the real door · Firestore rules

Security by structure, not hidden buttons

rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {

    // published reports: world-readable
    match /reports/{id} {
      allow read:  if resource.data.published == true;
      allow write: if isRole('qc_lead');
    }
    // samples & mappings: QC writes only
    match /samples/{id} {
      allow read:  if signedIn();
      allow write: if isRole('qc_lead');
    }
    // cupping: panellist edits only own row
    match /cupping_scores/{id} {
      allow write: if request.auth.uid
                   == request.resource.data.panelist_uid;
    }
  }
}
why this beats "hide the button"
  • a request with no valid role is refused at the database
  • bypassing your web UI changes nothing
  • PDPA: provenance PII stays on a QC-only path
test it sign in as roaster → attempt any write → PERMISSION_DENIED. The same ACL.md from Layer ② is now enforced.

Layer ③ · the workflow (UML Activity)

The gate blocks a bad report automatically

read the flow
  • chemistry in → rules → fork: UI + LLM run in parallel
  • join → the Citation Audit gate
  • a claim uncited or unhedged → [yes] reject/flag; otherwise [no] show report
AI checks AI a second agent audits the first agent's output and blocks publishing until it complies. That is agentic safety made structural.

How it runs · UML Deployment

Where each part lives — and how they talk

read it the browser only ever talks HTTPS; Firestore sits inside the Security-Rules boundary (nothing writes without a valid role); the LLM is reached only through the Citation Audit function — so no unaudited narrative can reach a user. Swap the LLM vendor without touching anything else.

Appendix B · rule.md — the agent's guardrail file

One file of NFRs the agent must obey

# rule.md — CoffeeAI guardrails (NFR)

R1  Every descriptor carries confidence +
    supporting_markers + citation. No uncited claim.
R2  Speculative claims must be hedged (tag speculative).
R3  Mapping engine is rule-based & explainable —
    no black-box model.            (NFR-01)
R4  No provenance PII on any public surface. (PDPA)
R5  Nothing publishes until Citation Audit passes.
how to use it
  • the agent reads it before every change
  • load-bearing rules become gates (Citation Audit) & Firestore rules
  • can't meet a rule yet? log it in KNOWN-GAPS.md — don't hide it
Create rule.md with the NFR guardrails above.
From now on, read rule.md before every change and
keep the build compliant. If a rule can't be met
yet, log it in KNOWN-GAPS.md instead of hiding it.
three files, three jobs CLAUDE.md = project brief for the AI · ACL.md = who can do what · rule.md = the NFR guardrails that turn into the seam, the audit gate, and the security rules.
