# UAT Qualitative User Evidence

**Evidence type:** Real-user UAT questionnaire feedback  
**Source:** `Advisor Log Responses.xlsx`, open-ended response fields  
**Participants:** U01–U10  
**Collection dates:** 2–4 November 2026

> **Important classification:** This is qualitative feedback collected during V1/V2 UAT, not a verbatim interview transcript. It is included as real-user evidence of observed opinions and reported pain points. The participant codes match the anonymized session-log mapping in [`uat-session-logs.md`](../../04-test%20plan/evidence/uat-session-logs.md). No names, email addresses, consent fields, or raw responses are published.

## Evidence summary

| Participant | Role | Reported pain point or need | Product decision / implication |
|---|---|---|---|
| U01 | Student | No specific difficulty was recorded; the participant described V1 as simpler but V2 as better overall. | Preserve V2 improvements without increasing interaction complexity. |
| U02 | Student | Status colours did not appear to change after a status update; V1 was perceived as easier to use. | Improve status feedback and make state changes visually clear. |
| U03 | Student | V2 looked better but was harder to use; the participant wanted notifications when a submission received a response or needed action. | Add clearer navigation and notification/status updates. |
| U04 | Student | The participant wanted clearer visual grouping and a more understandable layout. | Improve page hierarchy and information grouping. |
| U05 | Student | Task text and some fonts were too small; V1 felt easier for this participant. | Increase readable text size and review responsive typography. |
| U06 | Student | The interface felt crowded; update order was unclear. | Reduce visual density and make newest status/activity easier to identify. |
| U07 | Student | Menu choices and the next step were unclear; the interface should feel more friendly. | Improve navigation labels, affordances, and next-step guidance. |
| U08 | Student | The request process required too many steps; a single-page entry flow was preferred. | Reduce unnecessary page changes while retaining validation and consent. |
| U09 | Advisor | More advising topics were needed; email summaries needed more context and a direct system link. Saving a task also required redundant manual status updates, and scheduling could require multiple discussions. | Expand configurable categories, improve actionable notifications, and simplify task/status flow. |
| U10 | Advisor | V2 was more complete than V1 but still needed UX improvement. | Continue usability iteration rather than treating feature completeness as finished usability. |

## What this evidence supports

The responses support these problem themes:

1. **Status and follow-up visibility:** users need clear state changes, notifications, and activity ordering.
2. **Navigation and interaction cost:** users reported unclear next steps and too many request-form steps.
3. **Readability and visual hierarchy:** users requested larger text, clearer grouping, and a friendlier interface.
4. **Advisor workflow efficiency:** advisors need richer routed request context and less redundant status work.

These responses support the existence of user-perceived usability and workflow problems. They do **not** prove population-wide preferences, statistically significant improvement, or that every participant preferred V2. The quantitative V1/V2 timings and success rates remain in the [Before/After comparison](../../final/comparison-table.md).
